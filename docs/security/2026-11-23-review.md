# Security review — 2026-11-23

Partial assessment; not an ASVS certification or a 100/100 score.

## Verified fix

The isolate rate limiter cleared all counters once its map exceeded 10,000 identities. Identity churn could therefore restore a blocked client's budget. It now evicts expired counters only and rejects new identities at capacity. Existing identities retain their remaining budget. Regression tests cover saturation and expiry. This remains best-effort per isolate, not distributed bot or DDoS protection. Saturation can temporarily deny new legitimate clients; edge enforcement is still needed.

CI now audits build dependencies as well as production dependencies, failing for high/critical advisories. The initial full dependency audit reported zero vulnerabilities. Existing unit suite including the new regression tests: 1,629 passed; lint and typecheck passed.

## Existing controls observed in source

Secure HttpOnly host-scoped student and administrator session cookies; hashed session tokens; parameterized D1 queries; administrator audit logging; content publication gates; CSP and security headers; CI-gated deployment with smoke checks and rollback. These observations do not prove every route or deployed resource satisfies ASVS.

## Browser and offline constraints

Content delivered to a browser can be inspected, copied or recorded. Browser screenshots and external camera capture cannot be completely prevented. Blocking keyboard shortcuts or selection can harm accessibility and is not an authorization boundary. Public/free content and offline caches remain extractable. Signed URLs can limit online access duration but cannot revoke already downloaded bytes. Offline revocation cannot take effect until reconnection. Any stronger licensing design must preserve authorized offline study and use explicit entitlement rules, controlled offline bundles and tested renewal/revocation behavior.
